# ATM Forecast — MVP для папки отчетов

Локальная платформа, которая готова регулярно принимать CSV/XLSX-отчеты в папку `data/incoming`, сохранять историю остатков, находить пополнения и рассчитывать прогноз даты достижения минимального остатка.

> Важно: точный адаптер зависит от фактических названий колонок и структуры отчета. Достаточно положить один обезличенный пример CSV/XLSX — после этого настраивается `config/columns.json`.

## Архитектура

```text
Папка отчетов data/incoming
        │
        ▼
  importer.py (каждые 10 минут)
        │  CSV/XLSX, дедупликация, нормализация
        ▼
  SQLite atm_forecast.db
        │
        ├── snapshots — история каждого снимка
        ├── atms — справочник банкоматов и локаций
        ├── files — обработанные файлы
        └── events — пополнения и ошибки
        │
        ▼
  server.py — веб-панель http://127.0.0.1:8080
```

## Быстрый запуск

Требуется Python 3.10+ и `pandas`, `openpyxl`:

```bash
cd atm_forecast
python -m venv .venv
. .venv/bin/activate                 # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
mkdir -p data/incoming data/archive data/rejected
python importer.py                   # обработать имеющиеся файлы один раз
python server.py                     # открыть http://127.0.0.1:8080
```

После этого новые отчеты копируются в `data/incoming`. Для регулярной обработки:

```cron
*/10 * * * * cd /opt/atm_forecast && /opt/atm_forecast/.venv/bin/python importer.py >> logs/importer.log 2>&1
```

Планировщик не должен копировать файл в момент, когда он еще записывается. Рекомендуется сначала копировать с расширением `.tmp`, затем переименовывать в `.xlsx`/`.csv`.

## Формат входного отчета

Для вашей таблицы одна строка описывает один банкомат в один момент времени. Поддерживаемая структура:

| Поле | Пример |
|---|---|
| TID | 544830 |
| Serial number | 13-54544830 |
| Status 1–4 | OK / LOW |
| Currency 1–4 | UZS |
| Values 1–4 | 200000, 100000, 50000, 4000 |
| Count 1–4 | 533, 1909, 1935, 844 |
| Total remaining amount UZS | 402690000 |
| Total remaining amount USD | 0 |

Импортёр уже настроен на `TID`, `Serial number`, четыре кассеты и поля `Total remaining amount UZS/USD`. Он сохраняет как заявленный общий баланс, так и данные каждой кассеты (`status`, `currency`, `denomination`, `note_count`, расчетная сумма `denomination × note_count`). Это позволяет выявлять расхождения между итогом отчета и суммой кассет.

Если отчет Excel имеет две строки заголовка с объединенными ячейками, импортёр сначала пробует первую строку, а затем автоматически вторую.

Названия колонок настраиваются в `config/columns.json`. Импортёр понимает CSV и XLSX. Для XLSX берется первый лист по умолчанию; лист можно указать в конфиге.

## Настройка колонок

Откройте `config/columns.json` и замените значения справа на реальные заголовки из отчета:

```json
{
  "sheet_name": 0,
  "columns": {
    "atm_id": ["ATM ID", "Банкомат", "Терминал"],
    "reported_at": ["Время отчета", "Дата", "Timestamp"],
    "cash_total": ["Общий остаток", "Баланс", "Total cash"],
    "status": ["Статус", "State"],
    "address": ["Адрес", "Location"]
  }
}
```

Импортёр также пытается угадать колонки по встроенным синонимам. Если в одном файле несколько строк на кассеты, обязательно нужен столбец `cassette_id` и желательно `cassette_cash`/`note_count`; для первого MVP можно агрегировать отчет на стороне Excel до одной строки на ATM.

## Модель прогноза

1. Остатки сортируются по банкомату и времени.
2. Уменьшение остатка считается расходом.
3. Резкий рост считается событием пополнения и не включается в расход.
4. Средний дневной расход берется из последних 30 дней, минимум из 3 наблюдений.
5. Прогноз: `(текущий остаток - safety_cash) / средний расход в день`.
6. Если истории недостаточно, показывается `Недостаточно истории`.

Параметры находятся в `config/settings.json`:

- `safety_cash`: денежный резерв, ниже которого нужно предупреждать;
- `default_daily_burn`: запасной расход, если истории мало;
- `refill_jump_ratio`: коэффициент, с которого рост считается пополнением;
- `critical_days`: критический порог в днях.

## Важные ограничения MVP

- Если в строке нет времени, используется время из имени файла `cash-management-YYYY-MM-DD_HH_MM_SS.xlsx`; для текущих файлов оно настроено как UTC и переводится в часовой пояс Ташкента при отображении. Если формат времени поставщика окажется местным, параметр `filename_timezone` в `config/settings.json` нужно заменить на `Asia/Tashkent`.
- Система не должна трактовать пропуск отчета как нулевой остаток.
- Технические сбросы и замены кассет нужно подтвердить по образцу отчетов.
- Для точного расчета суммы пополнения и маршрутов инкассации потребуются фактические журналы пополнений.
- База SQLite подходит для пилота и одного сборщика; для нескольких пользователей/серверов следует перейти на PostgreSQL.

## Рекомендуемая эксплуатация

- сервер с постоянным доступом к папке либо сетевой шарой;
- отдельный пользователь ОС с минимальными правами;
- резервная копия `atm_forecast.db` ежедневно;
- хранение исходных отчетов в `data/archive` минимум 90 дней;
- логи в `logs/importer.log`;
- доступ к веб-панели ограничить VPN/локальной сетью.
